# Word template tags

The **Word document** button on the report screen fills `server/template.docx` using [docxtemplater](https://docxtemplater.com/) and downloads the result. A starter template containing every tag is generated by `node server/build-starter-template.mjs`; replace it with your own styled `.docx` and place the tags wherever you need them.

Rules:

- Text tags use single curly braces: `{address}`.
- Newlines in multi-line values (`overlays`, `ordinance`, `summary`) become line breaks in the document.
- Empty or missing values render as nothing, so unused tags are safe to leave in.
- Image tags use `{%...}` and **must each sit in their own paragraph**. Images render at 480×320 px.

## Private open space loop

One entry per proposed dwelling, using a paragraph loop — the `{#openSpace}` and `{/openSpace}` markers must each be in their own paragraph, and the paragraph between them repeats once per dwelling:

```
{#openSpace}

{label} — secluded: {secluded} m², total: {total} m²

{/openSpace}
```

Available inside the loop: `{label}` (`Dwelling 1`, `Dwelling 2`, …), `{secluded}`, `{total}`.

## Parking arrangements loop

Each proposed dwelling has an independent parking arrangement. The `{#parkingArrangements}` and `{/parkingArrangements}` markers must each be in their own paragraph, and the paragraph between them repeats once per dwelling:

```
{#parkingArrangements}

{number}: {arrangement}{other}

{/parkingArrangements}
```

## Existing canopy trees loop

One entry per tree added in step 20. Same paragraph-loop pattern as above:

```
{#existingTrees}

Tree {number} ({species}) — {spreadHeight}, status: {status}, located {location} — {retain}.

{/existingTrees}
```

Available inside the loop: `{number}`, `{species}`, `{spreadHeight}`, `{status}`, `{location}`, `{retain}`. The loop renders nothing when no trees have been added.

## No existing canopy trees

Render a single confirmation paragraph when the user has ticked "There are no existing canopy trees on this site" in step 20. Conditional sections render only when the data value is truthy:

```
{#noExistingTrees}

No existing canopy trees are present on the site, as confirmed by the arborist.

{/noExistingTrees}
```

## Clause 55 compliance tags

Each of steps 21 (B2-1), 22 (B2-2), and 23 (B2-3) records whether the proposal is compliant with the clause. The compliance flag becomes a "No" when the user ticks the box and a "Yes" when they don't; this maps directly to the presence of appeal rights:

| Tag | Content |
| --- | --- |
| `{streetSetbackCompliant}` / `{streetSetbackAppealRights}` | Compliance and appeal-rights for B2-1 |
| `{buildingHeightCompliant}` / `{buildingHeightAppealRights}` | Compliance and appeal-rights for B2-2 |
| `{streetSetbackDistance}` / `{streetSetbackNotes}` | B2-1 distance (m) and notes (defaults are filled in if the user leaves them empty) |
| `{#hasSecondaryStreetFrontage}...{/hasSecondaryStreetFrontage}` | Optional secondary-frontage setback block; include `{secondaryStreetSetbackDistance}` inside it |
| `{buildingHeightValue}` / `{buildingHeightNotes}` | B2-2 maximum height (m) and notes (defaults filled) |
| `{sideRearSetbacksMethod}` | `B2-3.1` or `B2-3.2` |
| `{sideRearSetbacksCompliant}` / `{sideRearSetbacksAppealRights}` | Compliance and appeal-rights for B2-3 |
| `{sideRearSetbacksNotes}` | Free-form notes (pre-filled with a default stating that all setbacks are deemed compliant) |

## Side & rear boundary loop

One entry per boundary added in step 23, with the floors pre-formatted into a single block:

```
{#sideRearBoundaries}

{name} ({southLabel}):

{floorsText}

{/sideRearBoundaries}
```

Inside the loop:
- `{name}` — e.g. "North boundary"
- `{southLabel}` — only populated when the chosen method is B2-3.2; otherwise blank
- `{floorsText}` — newline-separated list with each floor's `height`, calculated `required` setback, and `achieved` setback.

The loop renders nothing when no boundaries have been added.

### Required setback calculations

For your own reference if you replicate the logic in a Word template (otherwise the data already includes the computed values):

**B2-3.1** — `max(1, 1 + 0.3 × (h − 3.6) for 3.6 < h ≤ 6.9, then 1 + 0.99 + (h − 6.9) for h > 6.9)`.

**B2-3.2** — not south-facing: `3 m` up to 11 m height, `4.5 m` above. South-facing (between S 30° W and S 30° E): `6 m` up to 11 m height, `9 m` above.

**B2-4 walls on boundary (Standard B2-4)** — `allowable length = 10 + 0.25 × boundary length` metres.

**B2-5 site coverage (Standard B2-5)** — `computed = siteCoverage / siteArea × 100`. Max by zone: `NRZ 60%`, `GRZ 65%`, `RGZ/MUZ/HCTZ 70%`; other zones default to 60%.

**B2-6 access (Standard B2-6)** — allowable crossover width = `40% × frontage` if frontage < 20 m, otherwise `33% × frontage`.

## Cover image tag

Use a dedicated paragraph for the report cover image so it can be placed on the cover sheet and scaled to the correct size for Word export.

| Tag | Image |
| --- | --- |
| `{%coverImage}` | Front cover image uploaded in the report workflow |

## Image tags

Each is a 900×600 composite rendered exactly as shown in the wizard (satellite base with the layer drawn on top). All must be in dedicated paragraphs.

| Tag | Image |
| --- | --- |
| `{%satelliteImage}` | Satellite context with the parcel boundary |
| `{%zoningMap}` | Zoning map over satellite |
| `{%overlayMap1}` … `{%overlayMap4}` | One per overlay, in lookup order; unused tags render nothing |

If no address lookup has run (no images), the image tags render empty.

## Template errors

A malformed template (for example `{unclosed`) returns `502 Document generation failed` with the docxtemplater error detail. A missing `server/template.docx` returns `400` with a pointer to this file.
